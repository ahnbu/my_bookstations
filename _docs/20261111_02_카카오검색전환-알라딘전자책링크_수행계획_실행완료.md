# 카카오 책 검색 전환 + 알라딘 전자책 링크 자동 저장 수행계획

## 결론

- 알라딘 OpenAPI가 2026-10-30 영구 종료돼 책 검색·추가와 재고 갱신(새로고침 아이콘) 버튼이 함께 고장 났다. 책 정보는 **카카오 책 검색 API**에서 받고, 종이책·전자책 버튼은 **둘 다 알라딘 페이지**로 연결한다.
- 전자책 링크는 책을 **추가할 때 뒤에서 미리 찾아 저장**한다(사용자 확정). 알라딘 종이책 페이지 안의 「전자책」 탭 링크를 읽는다. **끝내 못 찾았거나 알라딘에 전자책이 없는 책은 전자책 버튼이 알라딘 전자책 검색 결과로 열린다**(2026-11-11 사용자에게 설명한 뒤 진행 지시를 받은 동작 그대로).
- 알라딘 API 시절에 저장한 책 678권은 메타데이터와 버튼 동작을 바꾸지 않는다(전자책 링크가 있으면 그대로, 없으면 지금처럼 버튼 없음).
- 남은 코드 작업: 0건(이 계획 안에서 모두 처리).

## 문제 (Complication)

1. 책 검색·추가가 안 된다. 검색 화면 전체, 일괄 검색, API 테스트 패널이 모두 알라딘을 부른다.
2. 재고 갱신(새로고침) 버튼과 책 추가 직후 재고 조회가 알라딘 실패로 중단된다. 기존 678권 모두 영향을 받는다.
3. 카카오에는 전자책 정보가 없다. 카카오 `url`은 다음 책 페이지라, 그대로 쓰면 종이책(다음)·전자책(알라딘)의 도착지가 갈린다. 사용자는 알라딘에서 사고 기존 구매도 알라딘이라 둘 다 알라딘이길 원한다.
4. 카카오 표지·설명은 알라딘보다 품질이 낮다. 재고 갱신 때 카카오 값으로 덮으면 기존 책의 좋은 데이터와 전자책 링크가 사라진다.

4. `.env.local`에 `KAKAO_REST_API_KEY`를 `~/.env` 값으로 한 줄 추가(값 출력 금지).
5. `pnpm dev`로 화면이 뜨는지(예시 서재 표시) headless로 1회 확인.

### 작업 1. 공용 로직 `lib/` (순수 함수)

- `lib/kakaoBook.ts`
  - `kakaoDocToAladdinItem(doc)`: 카카오 문서 1건 → `AladdinBookItem` 형태. 규칙:
    - `isbn13`: `isbn` 문자열을 공백으로 나눠 13자리 숫자 토큰을 고른다. 없고 10자리만 있으면 978 접두 + 체크숫자 계산으로 13자리로 바꾼다. 둘 다 없으면 `null`을 돌려 결과에서 뺀다.
    - `author`: `authors.join(', ')` / `pubDate`: `datetime` 앞 10자(`YYYY-MM-DD`), 없으면 `''` / `description`: `contents` / `publisher`
    - `cover`: thumbnail URL의 `fname` 값을 디코드해 `http://`를 `https://`로 바꾼 원본. `fname`이 없으면 thumbnail 그대로, 둘 다 없으면 `''`
    - `priceStandard`: `price`(음수·없으면 0) / `priceSales`: `sale_price`가 0 이상이면 그 값, 아니면 `priceStandard`
    - `link`: `aladinPaperUrl(isbn13)` = `https://www.aladin.co.kr/shop/wproduct.aspx?ISBN=<isbn13>` / `mallType`: `'BOOK'` / `subInfo`: `{}`
  - `toKakaoTarget(searchType)`: `Keyword`→없음, `Title`→`title`, `Author`→`person`, `Publisher`→`publisher`, `ISBN`→`isbn`. 그 밖의 값(예전 `eBook` 포함)은 `Keyword`처럼 처리.
- `lib/aladinEbook.ts`
  - `parseAladinPaperPage(html)` → `{ paperFound: boolean, ebook: { itemId: number, link: string } | null }`
    - `paperFound`: `<title>`이 ` | 알라딘`으로 끝나면 true. 제목이 `알라딘` 한 단어면 false(미등록).
    - `ebook`: `book_tab_box` 블록 안에서 `href="…ItemId=(\d+)…"` 다음 링크 글자가 `전자책`으로 시작하는 것. link는 `https://www.aladin.co.kr/shop/wproduct.aspx?ItemId=<번호>`.
  - `aladinPaperUrl(isbn13)`, `aladinEbookSearchUrl(title)`, `aladinIsbnSearchUrl(isbn13)` URL 생성 함수.
- 두 파일은 Node 타입 제거 실행(`node --test`가 .ts를 바로 import)이 가능하도록 enum·namespace 같은 TS 전용 문법을 쓰지 않는다.

### 작업 2. 서버 함수

- `api/search.ts` 교체: 쿼리 `Query, QueryType, MaxResults, start`를 받아 카카오 호출(`size`=min(MaxResults,50), `page`=start, `target`=작업1 매핑). 키는 `process.env.KAKAO_REST_API_KEY`. 응답은 `{ item: AladdinBookItem[] }`(변환 실패 건 제외). 카카오 오류는 `{ errorCode, errorMessage }` 형태로 그 상태 코드와 함께 돌려준다. 키가 없으면 500과 `KAKAO_REST_API_KEY is missing`.
- `api/aladin-ebook.ts` 신설: `GET ?isbn=<13자리>`. `/^\d{13}$/`가 아니면 400. 알라딘 종이책 페이지를 받아 `parseAladinPaperPage` 결과를 돌려준다. (실행 중 조정: 처음엔 12초 1회였으나, V-3에서 알라딘이 한 요청을 12초 넘게 멈추고 바로 다음 요청은 0.4초에 답하는 것을 확인해 **6.5초 × 2회 시도**로 바꿨다. 합계가 15초 함수 제한 안에 든다.)
  - 응답: `{ status: 'found', itemId, link, paperFound: true }` · `{ status: 'none', paperFound }` · `{ status: 'failed', reason }`(시간 초과·HTTP 오류).
  - `export const config = { maxDuration: 15 }`
- 로컬 개발: `vite.config.ts`의 알라딘 프록시(`/ttb/api`)를 지우고, `configureServer` 미들웨어로 `/api/search`·`/api/aladin-ebook`을 같은 `lib/` 함수로 처리한다(키는 `loadEnv`로 읽는 `KAKAO_REST_API_KEY`). 개발과 운영이 같은 `/api/*` 경로를 쓰게 되어 `aladin.service.ts`의 `IS_PRODUCTION` 분기를 없앤다.

### 작업 4. 스토어 — 재고 갱신과 전자책 저장

- `refreshBookInfo(id, isbn13, title, author, options?: { resolveEbook?: boolean })`:
  - 알라딘 재조회(`searchAladinBooks(isbn13,'ISBN')`)와 `알라딘 정보 조회 실패` throw를 없앤다. `createBookDataFromApis`에는 **저장돼 있던 책 메타데이터**(`originalBook`)를 넘긴다. 재고 병합 규칙은 그대로.
  - `resolveEbook`이 true이고 `shouldLookupEbook(book)`이 true면 `/api/aladin-ebook`을 불러 결과를 `applyEbookLookup(book, result, now)`로 반영한 뒤 같은 `book_data` 저장에 포함한다. 이 조회가 실패해도 재고 갱신은 계속한다.
  - DB 저장이 실패하면 화면 상태(`myLibraryBooks`·`librarySearchResults`·`libraryTagFilterResults`·`selectedBook`)를 `originalBook`으로 되돌린다(지금은 되돌리지 않음).
- 순수 함수 `utils/ebookLink.ts`(작업 5와 같은 파일):
  - `shouldLookupEbook(book, now)`: `subInfo.ebookList`가 비어 있고 `mallType !== 'EBOOK'`이며, `subInfo.ebookLookup`이 없거나 `status==='failed'`거나 `checkedAt`이 30일보다 오래됐으면 true.
  - `applyEbookLookup(book, result, now)`:
    - `found` → `subInfo.ebookList = [{ itemId, isbn: '', isbn13: '', priceSales: 0, link }]`, `subInfo.ebookLookup = { status: 'found', checkedAt: now }`
    - `none` → `subInfo.ebookLookup = { status: 'none', checkedAt: now }`. `paperFound === false`이고 **현재 `link`가 `aladinPaperUrl(isbn13)`과 같을 때만**(카카오로 새로 추가한 책) `link`를 `aladinIsbnSearchUrl(isbn13)`로 바꾼다. 원래 값은 `aladinPaperUrl(isbn13)`로 언제든 다시 만들 수 있으므로 따로 보관하지 않는다. 알라딘 시절 링크(`ItemId=` 포함)는 바꾸지 않는다.
    - `failed` → `subInfo.ebookLookup = { status: 'failed', checkedAt: now }`
    - 기존 `subInfo`의 다른 키(`paperBookList` 등)는 보존한다.
- 호출: `addToLibrary`의 백그라운드 호출(`:726`)과 목록의 단건 새로고침은 `{ resolveEbook: true }`. `bulkRefreshAllBooks`는 넘기지 않는다(678권 일괄 조회로 알라딘에 몰리지 않게).
- `types.ts`: `subInfo`에 `ebookLookup: z.object({ status: z.enum(['found','none','failed']), checkedAt: z.number() }).optional()` 추가.

### 작업 5. 화면 — 종이책·전자책 링크 한 곳에서 계산

- `utils/ebookLink.ts`에 `getStoreLinks(book)` → `{ paperLink: string|null, ebookLink: string|null }`. 위에서부터 먼저 걸리는 규칙:
  1. `mallType === 'EBOOK'`(예전 알라딘 전자책 검색으로 추가한 책): paper = `paperBookList[0].link || null`, ebook = `book.link`.
  2. paper = `book.link`.
  3. `ebookList[0].link`가 있으면 ebook = 그 링크.
  4. `book.link`에 `ItemId=`가 있으면(알라딘 API 시절 저장, 알라딘이 「전자책 없음」이라 한 책) ebook = `null` — 지금처럼 버튼 없음. 새로고침 뒤 조회 결과가 없음·실패여도 유지한다(완료 검수 2차 반영 — 처음엔 「`ebookLookup`이 없고」 조건이 있어 새로고침 뒤 검색 버튼이 생겼다).
  5. 그 밖(새 책의 `none`·`failed`·조회 전, 검색 결과 화면) ebook = `aladinEbookSearchUrl(제목)`.
- 적용: `components/MyLibraryListItem.tsx:252-262`(목록)·`:338-342`(격자 — 지금은 `ebookList[0].isbn13` 조건이라 링크 기준으로 바꿈), `components/BookSearchListModal.tsx:195-225`, `components/BookDetails.tsx:55-60`, `components/MyLibraryBookDetailModal.tsx:599-608`.
- `components/MyLibraryBookDetailModal.tsx:650-652`의 「ISBN (전자책)」 줄 제거(사용자: 「꼭 필요하진 않아」).
- `utils/isbnMatcher.ts`는 호출처가 없으므로 그대로 둔다(이번 범위 밖).

### 남은 리스크

- **마지막 수정은 외부 검수를 거치지 않았다.** 완료 검수 2차(검수 한도 2회 소진)의 지적 2건 — 저장 실패 시 같은 책의 편집까지 되돌림, 알라딘 시절 책이 새로고침 뒤 전자책 없음이어도 검색 버튼이 생김 — 을 고친 뒤에는 시험(V-1·V-2·V-9·V-11)으로만 확인했다. 두 번째는 `getStoreLinks` 규칙 4를 조회 기록과 무관하게 「링크에 `ItemId=`」로만 판정하도록 바꿨다(새로고침에서 전자책을 찾으면 버튼이 생긴다).

- 전자책 링크는 알라딘 웹페이지 구조에 기댄다. 구조가 바뀌면 새 책의 전자책 버튼이 검색 결과로 열린다(버튼이 깨지지는 않음).
- 카카오 검색 결과의 설명(`contents`)은 알라딘보다 짧다. 새로 추가하는 책에만 해당한다.

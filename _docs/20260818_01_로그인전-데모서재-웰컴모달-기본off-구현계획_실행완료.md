# 로그인 전 데모 서재 노출 + 웰컴 모달 기본 off 구현계획

**Goal:** 로그인하지 않은 방문자가 첫 화면에서 (1) 웰컴 모달 없이 (2) 실제 재고가 있는 예시 도서 10권이 채워진 "내 서재" 화면을 보고 서비스의 사용법과 결과물을 즉시 파악한다.

**Architecture:** 기존 `MyLibrary`의 로그인 사용자 경로는 건드리지 않는다. 비로그인 분기에서만 읽기 전용 `DemoLibrary`를 렌더하고, 데이터는 운영 DB에서 1회 추출한 정적 스냅샷(JSON)을 번들에 포함한다. 웰컴 모달은 전역 저장소가 없는 현재 구조를 그대로 두고 기본값만 뒤집는다.

**Tech Stack:** Vite 6, React 19, TypeScript 5, Zustand, Tailwind, Supabase(조회 전용), node:test + Playwright

## 1. 배경과 문제 진단

### 1-1. 웰컴 모달이 시크릿 창에서 계속 뜨는 원인

| 위치 | 사실 |
|---|---|
| `components/DefaultSettingsContent.tsx:138` | 관리자 토글이 `localStorage['adminWelcomeMessageSettings']`에만 저장된다. 서버 저장 경로가 없다 |
| `components/WelcomeModal.tsx:10` | 같은 localStorage 키에서만 설정을 읽는다 |
| `components/WelcomeModal.tsx:22` | 키가 없으면 **기본값 `enabled: true`** 를 반환한다 |
| `App.tsx:75` | `hasVisited` 키도 브라우저 로컬이라 시크릿 창은 항상 "첫 방문"이다 |

즉 관리자 토글은 관리자 본인 브라우저에만 적용되고, 외부 방문자에게는 **항상 기본값 `true`** 가 적용된다. 현재 구조에서 "전역 off"는 성립하지 않는다.

### 1-2. 로그인 전 화면이 비어 보이는 원인

`components/MyLibrary.tsx:826`의 비로그인 분기가 안내문 3줄만 렌더한다. 검색 폼은 비로그인에서도 동작하지만, 서비스의 핵심 산출물(도서관별 재고 배지가 붙은 서재 목록)은 로그인 전에는 전혀 노출되지 않는다.

## 5. 데이터 설계

### 5-1. 스냅샷에 담는 필드

`SelectedBook` 전체가 아니라 화면 렌더에 필요한 최소 필드만 담는다.

- 서지: `id`, `title`, `author`, `publisher`, `pubDate`, `cover`, `isbn13`, `link`, `categoryName`, `mallType`
- 사용자 활동(연출값): `addedDate`, `readStatus`, `rating`, `isFavorite`, `customTags`
- 재고: `stock_*` 12개 컬럼 전부

**제외**: `note`(개인 메모), `description`(번들 비대), `gwangjuPaperInfo` / `gyeonggiEduEbookInfo` / `gyeonggiEbookInfo` / `siripEbookInfo`(원본 응답. 배지는 `stock_*`만 사용하고, 원본이 없으면 `isError`가 `false`로 평가되어 안전하다), `autoTags`(자동 태그 규칙은 계정 설정에 종속되므로 데모에서는 사용하지 않는다).

### 5-2. id 충돌 방지

데모 도서 `id`는 `-1` ~ `-10`의 음수를 부여한다. 실 DB의 `user_library.id`는 양수이므로 상세 모달·선택 상태와 충돌하지 않는다.

### 5-3. 태그 표시

`MyLibraryListItem`은 `settings.tagSettings.tags`에서 태그 정의를 찾는다. 비로그인 기본 설정에는 `default_personal` 하나뿐이라 데모 태그가 표시되지 않는다. 전역 설정을 오염시키지 않기 위해 `tagsOverride` prop을 추가하고, `DemoLibrary`에서만 `DEMO_TAGS`를 주입한다.

### 5-3a. 상호작용 차단 방식 (읽기 전용 보장 근거)

`components/MyLibraryListItem.tsx`는 `useSettingsStore` 하나만 import하고 `useBookStore` / `useUIStore` / `getState()`를 전혀 호출하지 않는다(파일 상단 import 블록 및 전체 grep 결과 0건). 좋아요·별점·읽음상태·새로고침·상세열기·메모는 **전부 부모가 넘긴 props 콜백**(`onToggleFavorite`, `onUpdateRating`, `onUpdateReadStatus`, `onRefresh`, `onOpenDetail`, `onNote*`)으로만 처리된다.

따라서 `DemoLibrary`가 이 콜백들을 로그인 안내로 바꿔 넘기면, 데모 도서(음수 id)에 대한 스토어 액션이나 Supabase 요청은 구조적으로 발생할 수 없다. 별도의 `isDemo`/`readOnly` 플래그를 컴포넌트 내부에 넣지 않는 이유가 이것이며, 이 전제는 Phase 4의 "`useBookStore`/`useUIStore` import 부재" 단언으로 회귀 검증한다.

카드 내부의 외부 링크(도서관 검색 URL, 알라딘 상품 링크)는 `<a target="_blank">`이며 앱 상태를 바꾸지 않으므로 데모에서도 그대로 둔다.

### 5-4. 도서 선정 기준

1. 6개 배지 각각 `total > 0`인 도서가 최소 1권
2. 광주시 관내 다권 소장 스테디셀러 우선(대출로 인한 재고 변동이 적어 스냅샷이 오래 유효)
3. 표지가 있는 도서(`cover` 유효)
4. 별점·읽음상태·좋아요를 섞어 UI 요소가 비어 보이지 않게 구성

### 5-5. 추출 절차 (갱신 시 재사용)

Supabase MCP `execute_sql`로 대상 계정의 서재에서 후보를 조회한다.

select ul.id, ul.book_data->>'title' as title, ul.book_data->>'author' as author, ul.stock_gwangju_toechon_total, ul.stock_gwangju_other_total, ul.stock_sirip_subs_total, ul.stock_sirip_owned_total, ul.stock_gyeonggi_total, ul.stock_gyeonggi_edu_total from user_library ul join auth.users u on u.id = ul.user_id where u.email = 'byungwook.an@gmail.com' and coalesce(ul.stock_gwangju_toechon_total,0) + coalesce(ul.stock_gwangju_other_total,0) + coalesce(ul.stock_sirip_subs_total,0) + coalesce(ul.stock_sirip_owned_total,0) + coalesce(ul.stock_gyeonggi_total,0) + coalesce(ul.stock_gyeonggi_edu_total,0) > 0 order by ul.created_at desc limit 200;

선정한 10권의 상세는 두 번째 쿼리로 다시 조회해 `data/demoLibrary.json`에 슬림 필드만 옮긴다. **두 번째 쿼리는 그대로 복사해 실행하는 완성 SQL이 아니다.** 실행자는 첫 쿼리 결과에서 선정한 10개 `user_library.id`를 쉼표로 이은 정수 리스트를 `in (...)` 자리에 직접 채워 문장을 완성한 뒤 실행한다(예: `where ul.id in (101, 205, 318, ...)` 형태로 실제 정수 10개를 나열한다).

조회할 컬럼: `ul.id`, `ul.book_data`, 그리고 `stock_gwangju_toechon_total`, `stock_gwangju_toechon_available`, `stock_gwangju_other_total`, `stock_gwangju_other_available`, `stock_gyeonggi_edu_total`, `stock_gyeonggi_edu_available`, `stock_sirip_subs_total`, `stock_sirip_subs_available`, `stock_sirip_owned_total`, `stock_sirip_owned_available`, `stock_gyeonggi_total`, `stock_gyeonggi_available`. 대상 테이블은 `user_library`, 조건은 위에서 선정한 id 목록에 대한 `in` 조건 하나뿐이다.

Supabase 프로젝트는 `library_book_manager`(project_id `ugzruzaywohbynjzjesm`)이며, 루트 `.env.local`의 프로젝트 ref와 일치함을 확인했다. 두 쿼리 모두 조회 전용이라 영구 데이터를 변경하지 않는다.

## 6. 실행 단계

### 실행 웨이브

이 계획은 **단일 실행자가 Wave 1 → 4를 순차 수행**한다. 병렬·서브에이전트 실행을 전제하지 않는다.

| 웨이브 | 내용 | 선행 조건 | 병렬 가능 |
|---|---|---|---|
| Wave 1 | Phase 1 — 웰컴 모달 기본 off | 없음 | 불가(단독) |
| Wave 2 | Phase 2 — 데모 스냅샷 확보 | 없음(Wave 1과 파일 충돌 없음) | 불가(단독) |
| Wave 3 | Phase 3 — DemoLibrary 컴포넌트 | Wave 2의 `data/demoLibrary.ts` 완료 | 불가(단독) |
| Wave 4 | Phase 4·5 — 검증·문서·커밋 | Wave 1~3 전부 완료 | 불가(단독) |

Wave 3은 Wave 2의 산출물을 import하므로 순서를 앞당길 수 없다. Wave 4의 테스트는 Wave 1의 기본값 변경을 함께 단언하므로 Wave 1이 반드시 선행한다.

### 브라우저 검증 공통 규칙

- 모든 Playwright 실행은 **headless 모드**로 한다. `chromium.launch({ executablePath, headless: true })`처럼 `headless: true`를 명시하고, 기존 테스트의 기본값 의존([tests/book-search-quick-add-ui.test.mjs:92](../tests/book-search-quick-add-ui.test.mjs))을 따르지 않는다. 창을 띄우는 예외는 두지 않는다.
- 판정 증거는 `node --test`의 종료코드와 단언 실패 메시지로만 남긴다. 사람 눈 확인, 스크린샷 육안 대조를 완료 기준에 넣지 않는다.
- 비로그인 화면은 Supabase 세션 없이 접근 가능하므로 로그인 절차가 필요 없다. 로그인 상태 회귀는 실제 계정 로그인 대신 **`data/demoLibrary.json` 미사용 경로가 그대로인지 소스 단언**으로 확인한다(실계정 자격증명을 테스트에 넣지 않는다).

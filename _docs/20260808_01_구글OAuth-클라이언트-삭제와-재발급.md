# 구글 OAuth 클라이언트 삭제와 재발급

> **한 줄**: 구글 로그인이 `401 deleted_client`로 막혀 있었다. 2026-04-23에 클라이언트가 지워졌고, 새로 발급해 복구했다.

## 1. 증상

로그아웃 상태에서 「Google 계정으로 계속하기」를 누르면 구글이 이 화면을 돌려줬다.

```
액세스 차단됨: 승인 오류
The OAuth client was deleted.
401 오류: deleted_client
```

**나머지 화면은 전부 멀쩡했다.** 서재·검색·도서관 조회가 정상이라 서비스가 죽은 것으로 보이지 않았다.

## 2. 원인

구글 클라우드 감사 로그(400일치)를 조회해 확정했다.

```bash
gcloud logging read 'protoPayload.serviceName="clientauthconfig.googleapis.com"' \
  --project=gen-lang-client-0500434550 --limit=20 --freshness=400d \
  --format="table(timestamp,protoPayload.methodName,protoPayload.authenticationInfo.principalEmail,protoPayload.resourceName)"
```

| 시각 (UTC) | 메서드 | 대상 |
|---|---|---|
| 2026-04-23 11:20:30 | `CreateClient` | `187gdec…` |
| 2026-04-23 11:21:56 | `CreateClient` | `1ktu5iu…` (현 `gws_CLI_v2`) |
| **2026-04-23 11:24:05** | 🔴 **`DeleteClient`** | **`gpk8sdg…`** ← 이 서비스가 쓰던 것 |
| 2026-04-23 11:24:08 | `DeleteClient` | `187gdec…` (방금 만든 것) |

구글 워크스페이스 CLI 관련 정리 작업 중에 함께 지워진 것으로 보인다. 서비스 계정이 아니라 사람이 콘솔에서 지웠다.

### 왜 3개월 반이나 몰랐나

| | |
|---|---|
| **설정값은 남아 있다** | 수파베이스에 저장된 클라이언트 ID·보안 비밀번호는 그대로다. 대시보드는 정상으로 보인다 |
| **기존 세션은 계속 산다** | 이미 로그인한 브라우저는 갱신 토큰으로 유지된다. **새로 로그인할 때만** 오류가 난다 |

### 복원은 불가능했다

구글 콘솔의 「삭제된 OAuth 클라이언트 복원」 목록이 비어 있었다(「표시할 OAuth 클라이언트가 없습니다」). **복원 창은 삭제 후 30일**인데 3개월 반이 지났다.

## 3. 조치

| 순 | 무엇 | 결과 |
|---|---|---|
| 1 | `gen-lang-client-0500434550`에 웹 클라이언트 `my-bookstation-web` 발급 | `870603021154-spn…` |
| 2 | 승인된 리디렉션 URI에 `https://ugzruzaywohbynjzjesm.supabase.co/auth/v1/callback` | 저장 확인 |
| 3 | 수파베이스 `library_book_manager` → Authentication → Sign In / Providers → Google에 ID·보안 비밀번호 교체 | 재조회 일치 |
| 4 | 인증 URL로 실제 로그인 | ✅ 서재(674권) 정상 진입 |

동의 화면(브랜드)은 손대지 않았다 — 이미 **프로덕션·외부**로 게시돼 있어 같은 프로젝트의 다른 클라이언트(`google-api`·`gws_CLI_v2`·Firebase 자동생성)에 영향이 없다.

발급에는 다른 프로젝트의 검증된 스크립트를 재사용했다 — `202608_공익활동_AI교육/완주테스트/scripts/google-oauth-setup.py`.

⚠️ **그 스크립트에 오탐이 하나 있다.** 클라이언트 생성 직후 상세 화면에서 URI가 이미 채워져 있는데도 「URI 칸이 아직 없다」로 판단해 빈 칸을 덧붙인다. 값을 `innerText`로 찾는데 `<input>`의 `value`는 거기 안 잡히기 때문이다. 이번에는 「저장」이 비활성이라 실제 설정은 오염되지 않았다.

## 4. 다음에 같은 일이 나면

**증상은 신규 로그인만 막히는 것이다.** 아래 순서로 5분이면 끝난다.

1. 이 서비스의 구글 클라이언트는 **`gen-lang-client-0500434550`**(콘솔 표시명 「Gemini API」)에 있다. 프로젝트 이름이 서비스명과 달라 목록에서 `bookstation`으로 찾으면 안 나온다
2. 수파베이스에 박힌 클라이언트 ID의 앞자리가 곧 **구글 프로젝트 번호**다 (`870603021154`)
3. 콘솔 → 클라이언트 목록에 그 ID가 없으면 삭제된 것이다. **30일 안이면 「삭제된 OAuth 클라이언트 복원」으로 되돌린다**
4. 지났으면 새로 발급하고 리디렉션 URI 한 줄(`…supabase.co/auth/v1/callback`)만 넣는다
5. 수파베이스 Providers → Google에서 ID·보안 비밀번호를 교체한다

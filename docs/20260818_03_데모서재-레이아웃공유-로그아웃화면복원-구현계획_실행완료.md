# 데모 서재 레이아웃 공유 · 로그아웃 화면 복원 구현계획

**Goal:** (1) 로그아웃·세션 만료 사용자가 데모 서재 대신 로그인 안내 화면을 본다. (2) 데모 서재의 그리드 뷰가 로그인 화면과 똑같이 렌더된다. (3) 레이아웃·열 수·정렬 규칙이 원본 한 곳에서만 정의되어, 이후 원본을 고치면 데모에 자동 반영된다.

**Architecture:** `MyLibrary`의 `if (!session)` 분기를 **로그인 이력** 기준으로 두 갈래로 나눈다. 로그인 이력이 없으면 데모, 있으면 데모 도입 전의 로그인 안내 화면을 복원한다. 레이아웃 컨테이너와 반응형 열 수는 `BookListContainer` / `useGridColumns`로 추출해 `MyLibrary`와 `DemoLibrary`가 같은 코드를 호출한다. 정렬 비교자는 `utils/librarySort.ts` 순수 함수로 추출한다. `DemoLibrary`는 스스로 작성했던 레이아웃·정렬 코드를 **삭제하고** 공유 코드를 호출한다. 로그인 사용자의 동작·스토어·네트워크 흐름은 바꾸지 않는다.

**Tech Stack:** Vite 6, React 19, TypeScript 5, Zustand, Tailwind, Supabase(조회 전용), node:test + Playwright

## 2. 사용자 확정 사항

대화에서 확정한 내용이다.

1. **로그아웃·세션 만료 시에는 데모를 띄우지 않는다.** 데모 도입 전 안내 화면을 복원한다. 기존 사용자 경험을 데모 때문에 희생하지 않는다.
2. **데모는 첫 방문(로그인 이력 없음)에만 보인다.**
3. **안내 화면에 "예시 서재 둘러보기" 링크는 넣지 않는다.** 본인이 포폴 화면을 확인할 때는 시크릿 창을 쓴다.
4. **데모는 기존 코드를 그대로 사용한다.** 레이아웃·열 수·정렬을 데모가 따로 짜지 않고 원본과 공유한다.
5. **데모 상단은 실물 화면과 같게 하고 안내 문구 띠 1줄만 둔다.** 현재의 `h2 "내 서재 미리보기"` + 설명 문단 블록은 실물에 없는 요소라 첫인상을 습작으로 만든다.
6. **로그인 사용자 화면의 동작은 바뀌지 않는다.**

## 4. 화면 분기 설계

### 4-1. 판정 규칙

| 조건 | 화면 | 부가 |
|---|---|---|
| `session` 있음 | 기존 `MyLibrary` | 변화 없음 |
| `session` 없음 + 로그인 이력 없음 | `DemoLibrary` | 상단 1줄 띠 |
| `session` 없음 + 로그인 이력 있음 | 로그인 안내 화면 | 만료인 경우 토스트 추가 |

### 4-2. 로그인 이력 판정

`localStorage`에 불리언 키 하나를 둔다. 기존 키(`hasVisited`, `adminDefaultSettings`, 개발노트 키)와 충돌하지 않는다.

- 키: `hasSignedIn`
- 기록: [useAuthStore.ts](../stores/useAuthStore.ts)의 `onAuthStateChange` 콜백에서 **`session`이 truthy이면 이벤트 종류를 가리지 않고** `'true'`를 저장한다
- **삭제하지 않는다.** 로그아웃해도 남긴다. 이 값이 "이 브라우저를 쓰는 사람은 이 서비스의 사용자다"라는 판정 근거다
- 개인 식별 정보가 아니다. 사용자 id·이메일을 저장하지 않는다

**`SIGNED_IN`만 보면 안 되는 이유 (기존 로그인 사용자 마이그레이션)**

설치된 `@supabase/supabase-js` 2.53.0은 아래 세 이벤트를 구분해 발생시킨다. 번들에서 확인했다.

| 이벤트 | 발생 시점 |
|---|---|
| `INITIAL_SESSION` | 구독 시점에 이미 세션이 있을 때 (= 로그인 상태로 페이지 로드) |
| `SIGNED_IN` | **새로 로그인 동작을 수행할 때만** |
| `TOKEN_REFRESHED` | 액세스 토큰 자동 갱신 |

`event === 'SIGNED_IN'`만 기록하면 **배포 시점에 이미 로그인돼 있던 기존 사용자의 브라우저에는 키가 남지 않는다.** 그 사용자가 로그아웃하거나 세션이 만료되면 안내 화면 대신 데모가 떠서 이 작업의 1번 목표가 그대로 실패한다. 따라서 판정 조건을 이벤트가 아니라 **세션 존재 여부**로 잡는다.

```
supabase.auth.onAuthStateChange((event, session) => {
  if (session) localStorage.setItem('hasSignedIn', 'true');
  // 아래에 기존 set({ session, user }) 및 SIGNED_IN 시 closeAuthModal 처리를 그대로 유지한다
  // 4-3의 SIGNED_OUT 만료 판정도 이 콜백 안에 함께 둔다
});
```

이 조건은 `INITIAL_SESSION`·`SIGNED_IN`·`TOKEN_REFRESHED`를 모두 덮으므로 별도 마이그레이션 스크립트가 필요 없다. 기존 사용자는 배포 후 **첫 페이지 로드 시점에** 자동으로 기록된다.

**감수하는 트레이드오프:** 한 번 로그인한 브라우저에서는 데모가 뜨지 않는다. 사용자 확정 사항 3에 따라 시크릿 창으로 확인한다.

### 4-3. 로그아웃과 만료 구분

`useAuthStore` 모듈 스코프에 `isExplicitSignOut` 플래그를 둔다.

- `signOut()` 진입 시 `true`로 세우고, `SIGNED_OUT` 이벤트 처리 후 `false`로 되돌린다
- **`signOut()`이 실패하면 `SIGNED_OUT`이 발생하지 않으므로 플래그가 `true`로 굳는다.** 현재 [useAuthStore.ts:19-24](../stores/useAuthStore.ts)는 에러를 `console.error`만 하고 반환하므로 이 경로가 실재한다. `try/finally`가 아니라 **에러 분기에서 명시적으로 `false`로 원복**한다. `finally`로 감싸면 정상 경로에서도 `SIGNED_OUT` 콜백보다 먼저 복원돼 만료로 오판할 수 있다

```
signOut: async () => {
  isExplicitSignOut = true;
  const { error } = await supabase.auth.signOut();
  if (error) {
    isExplicitSignOut = false;   // SIGNED_OUT이 오지 않는다. 굳는 것을 막는다
    console.error('Error logging out:', error.message);
  }
}
```
- `SIGNED_OUT`인데 플래그가 `false`면 **만료**로 판정하고 토스트를 띄운다
  - 문구: `로그인이 만료되었습니다. 다시 로그인해주세요.`
  - type: `info`
- 명시적 로그아웃은 [Auth.tsx:160](../components/Auth.tsx)의 기존 토스트가 이미 있으므로 **추가 알림을 띄우지 않는다**(중복 방지)

페이지를 새로고침하면 플래그가 사라지므로, 새로고침 이후에는 만료 토스트가 다시 뜨지 않는다. 안내 화면은 그대로 남으므로 상태 신호는 유지된다. 의도한 동작이다.

### 4-4. 로그인 안내 화면

`1a6c4d3`의 [MyLibrary.tsx:824-832](../components/MyLibrary.tsx) 블록을 그대로 복원한다. 새로 디자인하지 않는다.

```
<div className="mt-12 animate-fade-in text-center text-secondary p-8 bg-elevated rounded-lg shadow-inner">
  <h2 className="text-2xl font-bold mb-4 text-primary">내 서재</h2>
  <p>로그인 후 '내 서재' 기능을 사용해보세요.</p>
  <p className="text-sm mt-2">관심있는 책을 저장하고, 여러 기기에서 확인하세요.</p>
</div>
```

`components/LoggedOutLibraryNotice.tsx`로 분리해 `MyLibrary`가 렌더한다. 로그인 버튼은 추가하지 않는다 — 헤더에 이미 로그인 진입점이 있다.

### 9-4. 최종 사용자 관점 스크린샷 (증거 수집, 게이트 아님)

주요 반영: `hasSignedIn` 기록 조건을 `SIGNED_IN` → `session` truthy로 교정(기존 로그인 사용자 누락 방지), 육안 확인을 통과 조건에서 제거, `git diff -w` 전문 판독, `signOut()` 실패 시 플래그 원복.

2차의 "Bash 명령이 Windows에서 실패한다"는 지적은 Git Bash 실증(`/usr/bin/seq`·`grep`·`du`·`awk`)으로 반박하고, 셸 표기 추가로만 반영했다.

### 남은 리스크·한계

- **로그인 사용자 화면은 실계정 세션이 필요해 headless 테스트로 직접 검증하지 못했다.** diff 범위 판정(9-3)으로 대체했다.
- **`hasSignedIn`은 브라우저 단위다.** 한 번 로그인한 브라우저에서는 예시 서재를 볼 수 없다. 사용자 확정 사항 3에 따라 시크릿 창으로 확인한다.
- **필터 파이프라인은 여전히 두 벌이다.** 서버 RPC와 로컬 배열이라 구조가 달라 의도적으로 남겼다. 계약을 `docs/DEVELOPMENT.md`와 테스트로 고정했다.
- 배포 후 실제 만료 토스트는 refresh token이 실제로 무효화돼야 재현되므로 배포본에서 자연 발생을 기다려야 한다.

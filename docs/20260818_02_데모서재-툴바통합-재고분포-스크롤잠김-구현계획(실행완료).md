# 데모 서재 툴바 통합 · 재고 분포 현실화 · 스크롤 잠김 수정 구현계획

**Goal:** 로그인 전 방문자가 (1) 페이지를 정상적으로 스크롤하고 (2) 검색·정렬·태그 필터·좋아요 필터·뷰 전환을 직접 조작해보며 (3) 재고가 있는 책과 없는 책이 섞인 현실적인 서재 20권을 본다.

**Architecture:** 선행 작업(`docs/20260818_01_...(실행완료).md`)이 만든 `DemoLibrary`를 확장한다. 툴바는 스토어를 쓰지 않는 `MyLibraryToolbar`를 그대로 재사용하고, 검색·정렬·필터는 `DemoLibrary`의 로컬 `useState`와 배열 연산으로 처리한다. 네트워크 요청은 여전히 0이다. 스크롤 잠김은 `WelcomeModal`의 표시 조건을 단일 변수로 통합해 고친다.

**Tech Stack:** Vite 6, React 19, TypeScript 5, Zustand, Tailwind, Supabase(조회 전용), node:test + Playwright

---

## 1. 배경

선행 작업 배포 후 사용자가 확인한 문제 3건이다.

### 1-1. 페이지 스크롤 잠김 (Critical, 선행 작업의 회귀)

`components/WelcomeModal.tsx`의 `useEffect`가 `isWelcomeModalOpen`만 보고 `document.body.style.overflow = 'hidden'`을 설정한다. `welcomeSettings.enabled` 검사는 그보다 아래 렌더 가드(`if (!isWelcomeModalOpen || !welcomeSettings.enabled) return null`)에만 있다.

1. `App.tsx`가 `hasVisited` 없으면 `openWelcomeModal()` 호출 → `isWelcomeModalOpen = true`
2. `useEffect`가 body 스크롤을 잠근다
3. 렌더 가드가 `enabled: false`로 `null`을 반환해 **모달은 보이지 않는다**
4. 닫을 UI가 없으므로 잠금이 풀리지 않는다

기본값이 `true`이던 시절에는 모달이 보였고 닫으면 풀렸기 때문에 드러나지 않았다. 기본값을 `false`로 뒤집으면서 밟았다.

선행 작업의 UI 테스트는 `scrollWidth`(가로)만 단언하고 세로 스크롤 가능 여부를 확인하지 않아 이 회귀를 잡지 못했다.

### 1-2. 데모 서재에 툴바가 없다

`DemoLibrary`는 카드 목록만 렌더한다. 검색·뷰 전환·태그 필터·정렬·선택 UI(`MyLibraryToolbar`)를 쓰지 않아, 이 서비스의 특징적인 기능이 로그인 전에는 존재조차 드러나지 않는다.

### 1-3. 데모 도서의 재고 분포가 비현실적이다

선행 작업이 고른 10권은 **전부 6개 배지 모두 재고 있음**이다. 실제 서재 671권의 분포는 다음과 같다(2026-08-18 조회).

| 배지 개수 | 권수 | 비율 |
|---|---|---|
| 0개 | 103 | 15% |
| 1개 | 182 | 27% |
| 2개 | 141 | 21% |
| 3개 | 105 | 16% |
| 4개 | 75 | 11% |
| 5개 | 50 | 7% |
| 6개 | 15 | 2% |

즉 상위 2%만 모은 표본이었다. 원인은 선정 쿼리가 배지 커버리지를 1순위 내림차순으로 정렬해, "6/6만 뽑기"라는 가장 쉬운 해로 수렴한 것이다.

## 2. 사용자 확정 사항

- 데모 권수를 10권 → **20권**으로 늘린다.
- 재고는 여러 케이스를 섞는다.
- 세 항목(스크롤·데이터·툴바)을 **하나의 작업으로 묶어** 수정한다.

## 4. 데이터 설계

### 4-1. 파일

`data/demoLibrary.json`을 20권으로 교체한다. 구조와 슬림 필드 규칙은 선행 작업과 동일하다(`note`/`user_id`/`email`/`created_at` 제외, `description`은 빈 문자열, `id`는 `-1` ~ `-20`).

### 4-2. 목표 재고 분포 (20권)

| 배지 개수 | 권수 | 성격 |
|---|---|---|
| 0개 | 3 | 재고 없음. 모든 배지가 회색 |
| 1개 | 5 | 관내 종이책만 또는 전자책만 |
| 2~3개 | 6 | 가장 전형적인 케이스 |
| 4~5개 | 4 | 인기 도서 |
| 6개 | 2 | 어디에나 있는 책 |

추가 조건:
- `total > 0`이고 `available = 0`인 **대출중** 상태 도서를 3권 이상 포함한다.
- 6개 배지 각각에 대해 `total > 0`인 도서가 최소 1권씩 있어야 한다(모든 배지 종류가 화면에 한 번은 초록으로 나타나야 한다).
- 표지(`cover`)가 있는 도서만 고른다.

### 4-3. 태그 설계

데모 태그 6종을 정의한다. 색상은 `primary` 2개, `secondary` 2개, `tertiary` 2개로 배분해 `TagFilter`의 색상 우선 정렬이 눈에 보이게 한다.

| id | 이름 | 색 | 배정 권수(목표) |
|---|---|---|---|
| `demo_personal` | 개인 | primary | 7~9 |
| `demo_wisdom` | 지혜 | primary | 5~7 |
| `demo_growth` | 자기계발 | secondary | 4~6 |
| `demo_literature` | 문학예술 | secondary | 3~5 |
| `demo_science` | 과학 | tertiary | 3~4 |
| `demo_business` | 경영경제 | tertiary | 2~4 |

도서당 1~2개를 배정한다. 태그가 없는 도서는 두지 않는다(필터 결과가 비는 경험을 피한다).

`tagCounts`는 런타임에 `DEMO_BOOKS`에서 계산한다. JSON에 카운트를 하드코딩하지 않는다(도서 교체 시 불일치가 생긴다).

카운트 기준은 **전체 20권에 대한 정적 총량**이다. 검색어나 좋아요 필터를 적용해도 태그 옆 숫자는 변하지 않는다. 로그인 사용자의 `MyLibrary`도 서재 전체 기준 `tagCounts`를 쓰므로 같은 의미를 유지한다.

### 4-4. 별점·읽음상태·좋아요 분포

정렬과 필터가 의미 있게 보이도록 아래를 만족시킨다.

- 읽음상태: `완독` 6~8권, `읽는 중` 4~6권, `읽지 않음` 나머지 (세 값이 모두 존재)
- 별점: 0점 5권 이상, 1~5점이 고르게 분포
- 좋아요(`isFavorite`): 4~6권

## 5. 컴포넌트 설계

### 5-1. WelcomeModal 스크롤 잠김 수정

표시 조건을 단일 변수로 통합한다.

- `const shouldShow = isWelcomeModalOpen && welcomeSettings.enabled;`
- `useEffect`의 조건과 의존성 배열, 렌더 가드가 모두 `shouldShow`를 사용한다.
- ESC 핸들러의 조건도 `shouldShow`로 맞춘다.

`App.tsx`에서 미리 거르는 대안은 채택하지 않는다. 설정 읽기 로직이 두 곳으로 갈라져 같은 종류의 불일치가 재발한다.

### 5-2. TagFilter의 tagCountsOverride

`components/TagFilter.tsx`는 `useBookStore()`의 `tagCounts`를 직접 읽고, 카운트가 0인 태그를 화면에서 제외한다. 비로그인 상태에서는 스토어의 `tagCounts`가 비어 있어 데모 태그가 하나도 표시되지 않는다.

`tagCountsOverride?: Record<string, number>` optional prop을 추가하고, 내부에서 `tagCountsOverride ?? tagCounts`를 쓴다. 미전달 시 기존 동작이 그대로 유지된다(`MyLibraryListItem`의 `tagsOverride`와 같은 패턴).

`MyLibraryToolbar`는 이 prop을 `TagFilter`로 통과시키는 optional prop을 하나 더 갖는다.

### 5-3. DemoLibrary의 로컬 상태와 동작

`DemoLibrary`는 아래 로컬 상태를 갖는다. 스토어를 쓰지 않는다.

- `searchQuery: string`
- `sortConfig: { key: SortKey; order: 'asc' | 'desc' }` (초기값 `{ key: 'addedDate', order: 'desc' }`)
- `activeTags: Set<string>`
- `showFavoritesOnly: boolean`
- `viewType: ViewType` (초기값 `'card'`)

파생 목록은 `useMemo`로 계산한다. 정렬 규칙은 `MyLibrary`의 기존 구현과 동일한 의미를 유지한다.

- 검색: `title` 또는 `author`에 대한 대소문자 무시 부분 일치. 2자 이상일 때만 적용한다(`MyLibrary`와 동일 기준)
- 태그 필터: `activeTags`가 비어 있지 않으면 **모든 활성 태그를 가진** 도서만 남긴다(AND 조건, `MyLibrary`의 RPC 계약과 동일)
- 좋아요 필터: `isFavorite === true`
- 정렬: `pubDate`는 `new Date().getTime()` 비교, `readStatus`는 `완독 < 읽는 중 < 읽지 않음` 순서, 그 외 문자열은 `localeCompare(_, 'ko-KR')`, 숫자는 수치 비교

동작 구분:

| 조작 | 데모 동작 |
|---|---|
| 검색 | 실제 동작 |
| 정렬 6종(추가순·제목순·저자순·출간일순·별점순·읽음순) | 실제 동작 |
| 태그 필터 | 실제 동작 |
| 좋아요 필터 | 실제 동작 |
| 카드/리스트 뷰 전환 | 실제 동작 |
| 개별 선택·전체 선택 | 로그인 안내 |
| 일괄 태그 관리·삭제 | 로그인 안내 |
| 카드의 좋아요·별점·읽음상태·새로고침·상세·메모 | 로그인 안내 |

`MyLibraryToolbar`에 넘길 카운트는 다음과 같이 맞춘다.
- `totalBookCount`: 20
- `filteredBookCount`, `displayedBookCount`: 필터링 결과 길이
- `selectedBookCount`: 0 고정
- `isAllBooksShown`: `true` (페이지네이션 없음)
- `hasActiveFilters`: 검색어·활성 태그·좋아요 필터 중 하나라도 있으면 `true`

필터 결과가 0건이면 "조건에 맞는 책이 없습니다" 안내와 필터 초기화 버튼을 보여준다.

### 5-4. 읽기 전용 보장

`MyLibraryListItem`이 `useBookStore`/`useUIStore`를 참조하지 않는다는 선행 작업의 설계 계약을 그대로 유지한다. `MyLibraryToolbar` 역시 스토어를 참조하지 않는 순수 props 컴포넌트이며, `TagFilter`만 스토어를 읽으므로 `tagCountsOverride`로 우회한다. 이 세 가지를 회귀 테스트가 단언한다.

## 8. 브라우저 검증 공통 규칙

- 모든 Playwright 실행은 `chromium.launch({ executablePath, headless: true })`로 **headless를 명시**한다. 창을 띄우는 예외는 두지 않는다.
- 판정 증거는 `node --test`의 종료코드와 단언 실패 메시지로만 남긴다. 사람 눈 확인이나 스크린샷 육안 대조를 완료 기준에 넣지 않는다.
- 실계정 자격증명을 테스트에 넣지 않는다. 로그인 사용자 경로의 무회귀는 완료 게이트의 diff 리뷰로 판정한다.
